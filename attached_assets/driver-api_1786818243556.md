# Jatek Driver API — Documentation

**Base URL :** `https://ma.jatek.app`  
**Auth :** Toutes les requêtes protégées nécessitent un header `Authorization: Bearer <token>`  
**Content-Type :** `application/json`

---

## 1. Authentification

### `POST /api/auth/login`
Connexion par email/mot de passe.

**Public — aucun Bearer requis**

**Body**
```json
{
  "email": "driver@example.com",
  "password": "motdepasse"
}
```

**Réponse 200**
```json
{
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "user": {
    "id": 42,
    "name": "Ahmed Livreur",
    "email": "driver@example.com",
    "role": "driver",
    "phone": "+212600000000",
    "address": null,
    "avatarUrl": null,
    "isActive": true,
    "loyaltyPoints": 0,
    "createdAt": "2025-01-01T00:00:00.000Z",
    "assignedShopId": null
  }
}
```

**Erreurs**
| Code | Message |
|------|---------|
| 400 | Corps invalide (champs manquants) |
| 401 | `{"error":"Invalid email or password"}` |

---

### `POST /api/auth/send-otp`
Envoie un code OTP par WhatsApp (téléphone) ou email.

**Public**

**Body** — téléphone **ou** email
```json
{ "phone": "+212600000000" }
```
```json
{ "email": "driver@example.com" }
```

**Réponse 200**
```json
{
  "success": true,
  "channel": "whatsapp",
  "message": "OTP envoyé",
  "otpSent": true
}
```

**Erreurs** : 400 identifiant invalide · 429 trop de tentatives (attendre 1 min) · 502 échec provider

---

### `POST /api/auth/verify-otp`
Vérifie le code OTP et retourne un token JWT.

**Public**

**Body**
```json
{
  "phone": "+212600000000",
  "code": "123456",
  "intent": "login"
}
```
> Pour inscription : ajouter `"intent":"signup"`, `"name"`, `"email"`, `"password"` (≥ 8 chars)

**Réponse 200** (login existant)
```json
{
  "token": "eyJ...",
  "user": { "id": 42, "role": "driver", "..." },
  "isNewUser": false
}
```

**Erreurs** : 400 code expiré/invalide · 404 compte introuvable · 403 compte désactivé

### `PATCH /api/drivers/:id`
Met à jour le profil driver (disponibilité, infos véhicule…).

**Body (tous optionnels)**
```json
{
  "isAvailable": true,
  "vehicleType": "moto",
  "vehiclePlate": "12345-A-6",
  "name": "Ahmed Livreur"
}
```

**Réponse 200** : objet Driver mis à jour

---

### `POST /api/drivers/:id/complete-profile`
Complète le profil obligatoire pour accepter des livraisons.

**Body**
```json
{
  "vehicleType": "moto",
  "vehiclePlate": "12345-A-6",
  "nationalId": "BK123456",
  "licenseNumber": "LIC-001",
  "photoUrl": "https://..."

```
> `vehicleType`, `vehiclePlate` (≥ 3 chars), `nationalId` (≥ 4 chars) sont **requis**

**Réponse 200** : objet Driver avec `profileCompletedAt` renseigné

  "thisMonth": 1650.0,

### `PATCH /api/drivers/me/push-token`
Enregistre ou met à jour le token Expo Push pour les notifications.

**Body**
```json

```

**Réponse 200**
```json

### `POST /api/drivers/:id/heartbeat`

**Body** : vide `{}`

```

## 3. GPS & Localisation

### `PATCH /api/drivers/:id/location`
Envoie la position GPS du driver. Publie les événements SSE aux clients/admins en temps réel.

**Body**
```json
{
  "latitude": 34.6814,
  "longitude": -1.9078,
  "destLat": 34.6900,
  "destLng": -1.9100
}
```
> `latitude` et `longitude` sont **requis**. `destLat`/`destLng` permettent de calculer l'ETA.

**Réponse 200**
```json
{
  "latitude": 34.6814,
  "longitude": -1.9078,
  "locationUpdatedAt": "2026-08-15T08:35:00.000Z",
  "eta": 7,
  "activeOrderIds": [103, 107]
}
```

---

### `GET /api/drivers/:id/location`
Position et disponibilité d'un driver (pour affichage client/restaurant).

**Réponse 200**
```json
{
  "latitude": 34.6814,
  "longitude": -1.9078,
  "locationUpdatedAt": "2026-08-15T08:35:00.000Z",
  "isAvailable": true,
  "name": "Ahmed Livreur"
}
```

## 4. Commandes — Flux Driver

### Cycle de vie d'une commande pour le driver

```
ready (dispo) ──▶ picked_up (accepté) ──▶ en_route ──▶ delivered
                      │
              POST accept-delivery         PATCH status       POST confirm-delivery
```

---

### `PATCH /api/orders/:id/status`
Met à jour le statut de la commande pendant la livraison.

**Body**
```json
{
  "status": "en_route",
  "driverId": 7
}
```

**Transitions valides pour un driver**
| De | Vers |
|----|------|
| `picked_up` | `en_route` |
| `en_route` | `out_for_delivery` |

> ⚠️ `delivered` est **interdit** ici — utiliser `POST /api/orders/:id/confirm-delivery`

**Réponse 200** : commande complète avec items

---

### `POST /api/orders/:id/confirm-delivery`
Finalise la livraison via le code de remise client (4 chiffres).

**Body**
```json
{ "pickupCode": "7364" }
```

**Réponse 200** : commande avec `status: "delivered"`

**Erreurs**
| Code | Signification |
|------|--------------|
| 400 | Code incorrect ou format invalide |
| 403 | Pas le driver assigné |
| 404 | Commande introuvable |

## 5. Temps Réel — Socket.IO

### `https://ma.jatek.app/socket.io/`
Connexion Socket.IO permanente pour recevoir les commandes en temps réel. Le
chemin est `/socket.io/` sur l’origine Jatek, et non `/api/socket.io/`.
Socket.IO/Engine.IO doit être configuré en version 4.

Le client transmet le JWT dans les deux emplacements suivants afin de rester
compatible avec les clients Android et web :

```ts
io('https://ma.jatek.app', {
  path: '/socket.io/',
  auth: { token: JWT, driverId: 7 },
  extraHeaders: { Authorization: `Bearer ${JWT}` },
  transports: ['polling', 'websocket'],
});
```

Le serveur doit accepter `handshake.auth.token` et, si absent, le bearer
`handshake.headers.authorization`. Après validation du JWT et du rôle
`driver`, il doit associer la socket au chauffeur authentifié. `driverId`
transmis par le client est indicatif et ne doit jamais remplacer l'identité
du JWT.

### Origines autorisées

La configuration CORS du serveur Socket.IO doit autoriser :

| Origine | Usage |
|---------|-------|
| `https://driver.jatek.app` | Client web de production |
| absence d'en-tête `Origin` | Clients Android/iOS natifs |

Pour le développement local, ajouter explicitement l'origine du preview
utilisée, sans ouvrir `origin: '*'` en production. La connexion utilise le JWT
plutôt que des cookies, donc `credentials` peut rester à `false`.

### Événements chauffeur

Le serveur ne doit diffuser une commande qu'aux chauffeurs concernés :

| Événement | Cible | Payload minimal |
|-----------|-------|-----------------|
| `order_ready` | chauffeurs disponibles et éligibles | `{ orderId, ... }` |
| `order_assigned` | chauffeur auquel la commande est assignée | `{ orderId, driverId, order? }` |

Exemple de diffusion côté serveur :

```ts
io.to('drivers:available').emit('order_ready', {
  orderId: 103,
  restaurantName: 'Pizza Oujda',
  deliveryAddress: '15 Rue Hassan II',
  total: 85,
});

io.to(`driver_orders:${driverId}`).emit('order_assigned', {
  orderId: 103,
  driverId,
  order: fullOrder,
});
```

Le client se resynchronise ensuite via `GET /api/orders` et
`GET /api/orders/available`; le payload Socket.IO sert donc de signal temps
réel et ne remplace pas la réponse API autoritative.

> Le transport SSE `GET /api/events` reste documenté dans les anciennes
> versions de ce fichier pour les clients historiques. Le driver actuel
> utilise Socket.IO exclusivement et ne doit pas ouvrir les deux transports.

## 6. Tableau des Erreurs HTTP Communes

| Code | Signification |
|------|--------------|
| 400 | Données invalides ou manquantes |
| 401 | Token absent ou expiré |
| 403 | Action non autorisée pour ce rôle |
| 404 | Ressource introuvable |
| 409 | Conflit (commande déjà prise) |
| 412 | Pré-condition échouée (profil incomplet) |
| 429 | Trop de requêtes |
| 502 | Échec service externe (SMS/WhatsApp) |

## 7. Exemple de flux complet

```bash
# 1. Login
TOKEN=$(curl -s -X POST https://ma.jatek.app/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"driver@example.com","password":"motdepasse"}' \
  | jq -r '.token')

# 2. Récupérer le profil driver
curl https://ma.jatek.app/api/drivers/me \
  -H "Authorization: Bearer $TOKEN"

# 3. Passer en ligne
curl -X PATCH https://ma.jatek.app/api/drivers/7 \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"isAvailable": true}'

# 4. Écouter les commandes disponibles (SSE)
curl -N https://ma.jatek.app/api/events?channels=available_orders,driver_orders:7 \
  -H "Authorization: Bearer $TOKEN" \
  -H "Accept: text/event-stream"

# 5. Accepter une commande
curl -X POST https://ma.jatek.app/api/orders/103/accept-delivery \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"driverId": 7}'

# 6. Mettre à jour la position GPS
curl -X PATCH https://ma.jatek.app/api/drivers/7/location \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"latitude": 34.6850, "longitude": -1.9050}'

# 7. Changer statut en route
curl -X PATCH https://ma.jatek.app/api/orders/103/status \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"status": "en_route", "driverId": 7}'

# 8. Confirmer la livraison
curl -X POST https://ma.jatek.app/api/orders/103/confirm-delivery \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"pickupCode": "7364"}'
```
